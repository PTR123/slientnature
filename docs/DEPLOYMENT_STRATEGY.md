# PetKeeper部署方案对比指南

## 📊 当前方案: NAS集中部署

### 架构
```
NAS设备(一台服务器)
├── PostgreSQL数据库 (:5432)
├── Redis缓存 (:6379)
├── 后端API (:3001)
├── 前端Web (:3000)
├── Nginx反向代理 (:80/443)
└── Portainer管理界面 (:9000)
```

### 优点
✅ 部署简单，一键启动
✅ 数据在本地，完全掌控
✅ 无需维护多个服务器
✅ 前后端通信延迟低(同一内网)
✅ 成本低(只需NAS)
✅ 适合长期稳定运行

### 缺点
❌ NAS负载较重(数据库+应用+缓存)
❌ 需要NAS有足够内存(建议4GB+)
❌ 外网访问需要配置穿透(无公网IP)
❌ 扩展性受限(单点部署)

### 适用场景
- 个人/家庭使用
- NAS资源充足(内存4GB+)
- 数据隐私要求高
- 长期稳定运行
- 成本优先

## 🌐 方案B: 分开部署(推荐)

### 架构
```
前端部署: Vercel(免费CDN)
    ├── 全球CDN加速
    ├── 自动SSL证书
    ├── 自动部署(推送代码即更新)
    └── 月访问量100GB免费

后端部署: NAS
    ├── PostgreSQL数据库
    ├── Redis缓存
    ├── API服务(:3001)
    └── 数据完全掌控

或后端部署: Railway(免费云平台)
    ├── 云平台托管
    ├── 500小时/月免费
    ├── 自动部署
    └── 无需维护服务器
```

### 优点
✅ 前端全球CDN加速，访问速度快
✅ Vercel前端免费，无限流量
✅ NAS负载减轻(只运行API+数据库)
✅ 前端自动部署，推送代码即更新
✅ 后端可选择NAS或云平台
✅ 更灵活的扩展性

### 缺点
❌ 需要配置两套环境
❌ 需要配置跨域
❌ 数据可能分布在云端和本地
❌ 需要更多部署知识

### 适用场景
- 用户分散在全球/外地
- 需要快速访问体验
- NAS资源有限(内存<4GB)
- 有一定技术基础
- 前端频繁更新

## 🚀 方案C: 全云端部署

### 架构
```
前端: Vercel(免费)
后端: Railway(免费额度500小时/月)
数据库: Supabase PostgreSQL(免费500MB)
Redis: Upstash Redis(免费10GB)
OSS存储: Cloudflare R2(免费10GB)
```

### 优点
✅ 完全免费(Vercel + Railway免费额度足够个人使用)
✅ 自动部署，无需手动运维
✅ 全球CDN，访问速度快
✅ 服务自动扩容
✅ 推送代码自动更新
✅ 无需购买服务器

### 缺点
❌ 数据在云端，隐私性降低
❌ 受平台限制(免费额度、规则)
❌ 可能需要付费升级(超出免费额度)
❌ 国内访问可能较慢(Railway服务器在国外)
❌ 平台故障会影响服务

### 适用场景
- 快速上线测试
- 个人项目/小团队
- 暂无服务器资源
- 体验现代部署方式
- 数据不敏感

## 🔧 如何修改为分开部署

### 步骤1: 创建后端专用docker-compose

我可以帮你创建一个`docker-compose-backend.yml`，只部署后端服务:

```yaml
version: '3.8'

services:
  postgres:
    # 数据库配置...

  redis:
    # Redis配置...

  backend:
    # 后端API配置...

  nginx:
    # 只代理API，不代理前端
    # 配置api.yourdomain.com -> backend:3001

  # 前端web服务删除
```

### 步骤2: 部署后端到NAS

```bash
# 使用后端专用配置部署
docker-compose -f docker-compose-backend.yml up -d
```

### 步骤3: 部署前端到Vercel

```bash
# 安装Vercel CLI
npm install -g vercel

# 登录
vercel login

# 部署前端
cd pet-keeper
vercel

# 配置环境变量(Vercel Dashboard):
# NEXT_PUBLIC_API_URL=https://api.yourdomain.com
```

## 📊 决策建议

### 选择方案A(NAS集中部署)如果:
- ✅ 你只有个人/家庭使用
- ✅ NAS内存充足(4GB+)
- ✅ 不想折腾多个平台
- ✅ 数据隐私最重要
- ✅ 想要最简单部署

### 选择方案B(Vercel前端 + NAS后端)如果:
- ✅ 你想要最好的访问体验(推荐!)
- ✅ NAS内存有限(<4GB)
- ✅ 前端需要频繁更新
- ✅ 有用户在外地访问
- ✅ 数据隐私重要，但前端体验也重要

### 选择方案C(全云端)如果:
- ✅ 你没有NAS或不想用NAS
- ✅ 想要最省钱
- ✅ 快速上线测试
- ✅ 数据隐私不重要
- ✅ 体验现代云部署
